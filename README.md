# Расписание с автозаменами

Flutter-приложение, которое показывает расписание занятий и **само подтягивает
замены**: находит на сайте учебного заведения ссылку на документ с заменами,
скачивает `.docx` из облака Mail.ru, разбирает таблицу и накладывает замены
поверх основного расписания.

Сервера у приложения нет — всё работает локально на устройстве.

## Как это устроено

```
сайт заведения ──► ссылка на cloud.mail.ru ──► .docx ──► разбор таблицы ──► SQLite
                                                                              │
основное расписание (.md, импорт вручную) ──────────────────► SQLite ─────────┤
                                                                              ▼
                                                            расписание дня с заменами
```

* **Основное расписание** импортируется вручную — Markdown-файлом.
  Формат описан в [`docs/SCHEDULE_FORMAT.md`](docs/SCHEDULE_FORMAT.md),
  пример — в [`samples/schedule_example.md`](samples/schedule_example.md).
  В приложении есть готовый промпт, которым удобно превратить фото или таблицу
  расписания в нужный Markdown.
* **Замены** обновляются по кнопке (и по желанию — при запуске). Приложение
  ищет на странице ссылки со словом «замены», выбирает подходящую по дате,
  скачивает документ и разбирает его. Если сайт недоступен или разметка
  поменялась — можно задать прямую ссылку или выбрать `.docx` с устройства.

## Возможности

### Расписание

* День с переключением свайпом, по дням и по неделям.
* Числитель / знаменатель — с настройкой, какая неделя считается числителем.
* Подгруппы: можно скрыть пары чужой подгруппы.
* Замены подсвечиваются и показывают, что стояло в расписании раньше.
* Снятые пары («группа гуляет») и добавленные пары помечаются отдельно.
* Точки на днях недели, где есть замены — видно, не открывая каждый день.
* Пара, идущая прямо сейчас, выделяется; прошедшие приглушаются.
* Несколько групп в одной базе, переключение в шапке.

### Звонки

* Несколько наборов, каждый привязан к своим дням недели — будни и суббота
  обычно звонят по-разному.
* Задаются в том же Markdown-файле или правятся вручную на отдельном экране.

### Домашние задания

* Что задали, к какому числу и насколько обязательно: **обязательно**,
  **желательно**, **не критично**.
* Список сгруппирован по срокам, просроченное вынесено наверх.
* Предмет подставляется подсказкой из расписания группы.
* На карточке пары видно, есть ли по предмету незакрытое задание.

### Уведомления

* Напоминание перед звонком на пару — за 5/10/15/30 минут.
* Напоминание о домашке — за 1/2/3/7 дней до сдачи, в заданный час.
  О заданиях «не критично» не напоминает, чтобы шторка не превращалась в шум.
* Фоновая проверка замен: приложение само заглядывает на сайт раз в
  несколько часов и присылает уведомление, если что-то поменялось —
  не нужно открывать приложение, чтобы узнать.
* Тап по уведомлению открывает то самое место, о котором оно сообщает:
  нужный день, конкретное задание или экран замен — а не просто
  разворачивает приложение на текущем дне.
* Всё локально: планируется на устройстве и переживает перезагрузку.

### Данные

* Резервная копия одним файлом `.json` — расписание, звонки, замены,
  домашка и настройки. Восстановление показывает предпросмотр
  (сколько пар, замен, заданий, дата создания) перед необратимой заменой.
* На экране «Все замены» — время последнего обновления и лог «было →
  стало» для своей группы: видно, что именно поменялось, а не только
  итоговый результат.

### Внешний вид

* Светлая, тёмная и системная тема.
* Material You — цвета из обоев (Android 12+), либо 8 акцентов на выбор.
* AMOLED-режим с чёрным фоном, масштаб текста, компактные карточки.

### Диагностика

* Экран «Диагностика разбора» показывает, что именно приложение прочитало
  в документе. Нужен, чтобы подстроить парсер под реальный формат.

## Структура

```
lib/
  core/
    database/      таблицы и запросы drift (Lessons, Substitutions, AppMeta, Homeworks)
    notifications/ планирование локальных уведомлений и открытие нужного экрана по тапу
    background/    фоновая проверка замен через WorkManager
    backup/        экспорт и восстановление JSON-резервной копии
    settings/      настройки в SharedPreferences
    theme/         темы и палитра акцентов
    utils/         недели, чётность, форматирование дат
    error/         исключения и Failure
  features/
    schedule/      основное расписание: импорт .md, слияние с заменами, звонки, UI
    substitutions/ загрузка и разбор .docx с заменами, UI
    homework/      домашние задания и приоритеты
    settings/      экран настроек
```

Логика слияния замен вынесена в чистую функцию
[`schedule_merger.dart`](lib/features/schedule/domain/schedule_merger.dart) —
она покрыта тестами и не зависит от базы.

## Запуск

```bash
flutter pub get
```

```bash
dart run build_runner build --delete-conflicting-outputs
```

```bash
flutter run
```

Кодогенерация нужна после любых изменений в `lib/core/database/tables.dart`.

## Сборка APK

```bash
flutter build apk --release --target-platform android-arm64
```

Готовые сборки лежат в [релизах](../../releases).

## Тесты

```bash
flutter test
```

Покрыты: разбор Markdown-расписания и звонков, разбор `.docx` (тесты собирают
документ на лету), слияние замен с расписанием, вычисление чётности недели,
распознавание дат в тексте ссылок, домашние задания с приоритетами,
планирование напоминаний и миграция схемы базы.

## Настройка под своё заведение

Адрес страницы с заменами задаётся в **Настройках** — по умолчанию стоит
`khamk.ru`. Если структура документа завуча отличается от ожидаемой,
загрузите `.docx` вручную и откройте **Диагностику разбора**: там видно,
какие колонки распознались, а какие строки парсер не понял.

## Известные ограничения

* Разбор `.docx` и поиск ссылки на сайте написаны по предположениям о формате —
  на настоящих документах ещё не проверялись.
* Сборка только под `arm64`. 32-битная не собирается: связка CMake 3.22
  и NDK 28 не конфигурирует armv7-тулчейн.
